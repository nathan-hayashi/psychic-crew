# RELIABILITY-REGISTRY — every suite section mapped to what it protects (REGISTRY-1)

The missing layer between "we have suites" and "a claim is provably covered": one row per
suite SECTION across the five parent scripts. The EXTRACTION SPEC is shared with the suite's
reverse arm and declared here: lines matching `echo "== … =="` at line start (any indent),
EXCLUDING lines containing `$(` or `%s` — the live-evidence banner and the summary printfs are
output, not sections. MATURITY IS MECHANICAL, never archaeology: a section whose span carries
a firing-control line (`control fires` / `fire-probe`) is `proven`; everything else is
`experimental` — the split is measured (14 proven / 30 experimental at birth),
not flattered. Columns: behavior_id · invariant · oracle · proving_assertions (file:needle) ·
maturity.

Per-assertion granularity is DECLARED v2 with its wake named: when a registry row's section is
implicated in a real defect, that section's rows split to per-assertion at the fixing gate.
STANDING COST, stated: every later gate that adds a suite section adds its registry row in the
same gate — the reverse arm forces it mechanically.
